\section*{Executive Summary}
Agentic autonomy is shifting the unit of output from \emph{human-hours} to \emph{agent-hours}. That shift can increase decision tempo and execution density beyond human relevance windows, especially in contested environments where connectivity is intermittent and deception is routine.

The \textbf{Agent Control Plane (ACP)} makes this shift \textbf{fieldable}. It standardizes agent identity, delegated authority, long-running execution, and mediated action through gateways. It also produces evidence and replay artifacts for continuous authorization and after-action reconstruction.

This paper presents ACP-RA as a DoD CIO style reference architecture: purpose, principles, technical positions, patterns, and vocabulary. It guides and constrains downstream solution architectures rather than prescribing a single implementation.

\section{Scope and Non-Goals}
\subsection*{In scope}
\begin{itemize}
\item Enterprise, intelligence, and operational-support agents that plan, coordinate, and invoke tools/actions within bounded authority.
\item Multi-agent ensembles (swarms) and their coordination, messaging, shared state, budgets, observability, and containment.
\item Work-unit management for long-running and parallel agent execution (checkpointing, dependencies, cancellation, supervision).
\item Policy-as-code, evaluation-as-gate, and evidence generation for continuous authorization.
\item Cross-enclave federation and cross-domain handoffs (identity, context, and evidence).
\end{itemize}

\subsection*{Out of scope}
\begin{itemize}
\item Tactical employment guidance for autonomous weapons.
\item Authorization of use-of-force decisions.
\item Any design that bypasses applicable weapon system autonomy policy (see DoDD 3000.09).
\end{itemize}

\section{Problem Statement}
The Department is moving toward intent-driven systems that plan and act through tools. These systems can run many tasks in parallel and for long periods. Without a control plane, speed becomes unmanaged risk: unclear authority, uncontrolled data movement, fragile tool integration, weak evidence, and poor containment.

ACP-RA defines the required control surfaces to make autonomy governable at scale.

\section{Strategic Drivers}
\begin{itemize}
\item \textbf{A posture of acceleration:} platforms must support rapid onboarding and change while staying governable and reversible.
\item \textbf{Supervision at scale:} the core problem shifts from whether agents can do tasks to whether humans can supervise many long-running parallel tasks.
\item \textbf{Contested and degraded environments:} deception, poisoning, cascade failures, and intermittent connectivity are baseline constraints.
\item \textbf{Federation:} cross-Service, cross-agency, and cross-enclave interoperability is unavoidable; the ACP must be protocol-neutral.
\end{itemize}

\section{Architectural Principles}
\begin{enumerate}
\item Agents are NPEs, not apps.
\item Centralize policy decisions; distribute enforcement.
\item Default deny; allow by explicit trust scope.
\item The doing boundary is explicit and mediated.
\item Evidence is first-class.
\item Rollback and containment are capabilities.
\item Context engineering is governed data movement.
\item Evals and monitoring are gates.
\item Budgets are policy.
\item Tools and skills are a supply chain.
\end{enumerate}

\section{Core Vocabulary}
\textbf{Agent:} software actor that can plan, retrieve context, communicate, invoke tools, and execute actions within bounded authority.

\textbf{Persona:} controlled mission role for an agent; used by policy.

\textbf{Trust scope manifest:} signed, versioned contract defining delegated authority and constraints (tools/actions, consequence tier, environment, thresholds, budgets, evidence requirements, degraded modes).

\textbf{Work unit:} durable, supervised task thread for long-running and parallel execution that binds scope context, budgets, dependencies, checkpoint policy, sandbox provenance, and an evidence root.

\textbf{Policy bundle:} signed, versioned policy rules consumed by enforcement points.

\textbf{Context bundle:} replayable artifact representing retrieved context with provenance and integrity metadata and stable hash identifiers.

\textbf{Action envelope:} signed record of an attempted action/tool call including policy decision and evidence pointers.

\textbf{Inter-agent message envelope:} signed record of agent-to-agent messaging including schema, TTL, rate class, and provenance.

\textbf{Ensemble (swarm):} first-class multi-agent object with explicit governance, budgets, and containment semantics.

\section{Consequence Tiers and Required Controls}
\begin{longtable}{p{0.12\linewidth} p{0.46\linewidth} p{0.36\linewidth}}
\textbf{Tier} & \textbf{Representative activities} & \textbf{Minimum controls} \\
\hline
T0 & Drafting, summarization, read-only analysis. & Agent identity, data tag controls, basic evidence, deny-by-default tool use. \\
T1 & PR creation, ticket automation, recommendations (no direct apply). & Tool mediation, budgets, baseline evaluation, drift monitoring. \\
T2 & Production changes, account/permission changes, external comms, GUI ops. & Human-on-the-loop approvals, dual control, enhanced evidence, rollback rehearsal. \\
T3 & Life/safety or mission-critical actions. & Strict deny-by-default, quorum approvals, constrained degraded modes, full-fidelity evidence triggers. \\
\end{longtable}

\textbf{Composition rule:} when scopes combine, authority composes by intersection, never union.

\section{Technical Positions (Required Control Surfaces)}
\begin{itemize}
\item TP1: Agent identity as NPE (ICAM-aligned).
\item TP2: Trust scopes are signed, versioned, and enforceable.
\item TP3: Work units are first-class governance objects.
\item TP4: Tool/action gateway mediates all doing.
\item TP5: Tools and skills onboarded through supply-chain controls.
\item TP6: Inter-agent gateway governs messaging and prevents cascades.
\item TP7: Context/data gateway governs retrieval and context movement.
\item TP8: Model gateway governs routing and upgrades.
\item TP9: Evaluation harness gates promotion; monitoring gates runtime.
\item TP10: Evidence ledger is tamper-evident and queryable.
\item TP11: Degraded-mode behaviors are declared and enforced.
\end{itemize}

\section{Multi-Agent Governance}
Ensembles require explicit contracts: coordination pattern, arbitration rules, shared state governance, budgets and allocation, and containment without collapse.

\section{Contested and Degraded Operation}
ACP assumes poisoning, deception, and partial connectivity. Degraded modes are policy-driven safe behaviors (disconnected, intermittent, denied-model, human-handover).

\section{Patterns}
Work units as unit of supervision; policy-centered mesh; bulkhead gateways; budgeted autonomy; tool supply chain governance; evidence-first releases; ensemble contract.

\section{Metrics and Roadmap}
Define tempo, governance, swarm reliability, tool supply chain, adversarial robustness, and resource metrics. Maturity levels range from copilot sprawl to federated and contested operation.

\section{Conclusion}
ACP-RA treats autonomy as an engineered control system. It separates planning from doing, centralizes policy decisions while distributing enforcement, and makes evidence and containment first-class. This enables faster iteration without turning speed into unmanaged risk, including for multi-agent ensembles operating in contested and degraded environments.
