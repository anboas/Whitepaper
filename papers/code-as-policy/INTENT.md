## 1) Intent (what this paper does)
- Make the case that policy should be treated as a version-controlled, testable, reviewable artifact (not a static document).
- Provide a practical implementation path (process + tooling) for moving policy from Word/PDF workflows into pull requests.
- Give leaders a clear decision: adopt Code-as-Policy as the default operating model for policy development and change.
